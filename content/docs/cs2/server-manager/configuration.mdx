## Your own config files

`csm` rebuilds server files when it updates the game or the plugins. Files you edit inside `server-N/` can be lost. Put your own files in the overrides folder instead:

```text
~/overrides/game/
```

The folder mirrors the server's `game/` folder. `csm` copies it over the servers when it updates the plugins, so your files win. Examples:

| Your file | Goes to |
| --- | --- |
| Ready Up settings | `~/overrides/game/csgo/cfg/ReadyUp/` (`readyup.cfg` and one file per plugin) |
| CS2 configs | `~/overrides/game/csgo/cfg/` |

`~` is the home folder of the account that runs csm.

After a change, copy it to the servers. This also restarts them:

```bash
csm update-plugins
```

A plain `csm restart` does not copy the overrides.

## Where csm keeps its own files

`csm` keeps its state, logs and servers in the home folder of the account that runs it. To use another folder, set `CSM_ROOT` every time you run `csm`:

```bash
CSM_ROOT=/srv/csm csm
```

Most people do not need this.
