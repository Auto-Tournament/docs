## What you need

- Linux on `x86_64` or `arm64`. Debian and Ubuntu are the tested systems.
- An ordinary user account that will run the servers, with `sudo` for the one-time setup. csm refuses to run as root.
- At least 8 GB RAM, and 1 to 2 GB more for each server.
- About 70 GB of disk for CS2. In instance mode all servers share it; in classic mode each extra server adds about 2 GB.
- Docker only for the MatchZy Enhanced stack's shared MySQL database. See the [Docker install guide](https://docs.docker.com/engine/install/). csm does not install Docker for you.

csm installs the other packages it needs (SteamCMD, tmux, rsync, the 32-bit libraries and more) with `apt`. See [Server requirements](/modules/cs2/server-requirements) for the network ports.

## Install

Log in as the account that will run the servers, not as root.

<Steps>

<Step>

### Download csm

This downloads the latest `csm` for your CPU to `/usr/local/bin/csm`:

```bash
arch=$(uname -m); \
case "$arch" in \
  x86_64)  asset="csm-linux-amd64" ;; \
  aarch64|arm64) asset="csm-linux-arm64" ;; \
  *) echo "Unsupported architecture: $arch" && exit 1 ;; \
esac; \
tmp=$(mktemp); \
curl -L "https://github.com/Auto-Tournament/cs2-server-manager/releases/latest/download/$asset" -o "$tmp" && \
sudo install -m 0755 "$tmp" /usr/local/bin/csm && \
rm "$tmp"
```

Later, `csm self-update` updates csm itself.

</Step>

<Step>

### Set up the machine once

```bash
sudo csm setup-host
```

It installs the system packages and sets your account up to run csm: your servers keep running after you log out, and csm's files are yours. It never starts, stops or updates a server, and it is safe to run again. From now on, run `csm` as yourself, without `sudo`.

</Step>

<Step>

### Choose how to create servers

**With Auto Tournament 3.0** (recommended): let the platform create them.

```bash
csm instance config backend instances
csm plugins license noncommercial   # or commercial: Ready Up's license, answered once
csm plugins channel beta            # while Ready Up has only beta releases
csm link https://tournament.example.com -
csm agent install
```

Get the one-time code from **Servers → Machines → Add machine** in Auto Tournament, and paste it when `csm link` asks. Then create servers from the machine's card. The platform installs CS2 and Ready Up, and each server enrolls itself. See [Host a CS2 tournament](/guides/host-cs2-tournament).

**On its own**, or for Auto Tournament 2.x: run `csm`, and in the menu choose **Install** > **Install or redeploy servers**. The installer asks for:

- **Number of servers.** The default is 3.
- **Game port and GOTV port** of server 1. The defaults are `27015` and `27020`.
- **Hostname prefix, RCON password and max players.** Change the default RCON password.
- **GSLT.** Leave it empty. A GSLT only lists the server in the in-game server browser, and Valve can ban it on a server with the skins plugin. See [Game Server Login Token](/modules/cs2/server-requirements#game-server-login-token).
- **MatchZy storage and database**, which only matter for the MatchZy Enhanced stack.
- Update options: validate the game files with SteamCMD, update the plugins, and install the [update monitor](/cs2/server-manager/updates#the-update-monitor).

A fresh install uses Ready Up. For Auto Tournament 2.x, switch to the MatchZy Enhanced stack first with `csm plugins stack legacy`. See [Plugins and updates](/cs2/server-manager/updates).

</Step>

<Step>

### Wait for the download

The first install downloads CS2, about 70 GB. This can take a long time.

</Step>

<Step>

### Open the ports

Open the game ports and GOTV ports in your firewall. See [Ports](#ports) for the numbers. Players need UDP. MatchZy Enhanced servers also need TCP on the game port for RCON from Auto Tournament; Ready Up servers need no inbound port for the platform.

</Step>

</Steps>

## Ports

Server 1 uses game port `27015` and GOTV port `27020`. Each next server adds 10:

| Server | Game port (UDP and TCP) | GOTV port |
| --- | --- | --- |
| 1 | 27015 | 27020 |
| 2 | 27025 | 27030 |
| 3 | 27035 | 27040 |

## Install without the menu

`csm bootstrap` installs or redeploys the servers with no questions. Set the options as environment variables:

```bash
NUM_SERVERS=5 RCON_PASSWORD='a-long-random-password' csm bootstrap
```

| Variable | Default | What it sets |
| --- | --- | --- |
| `NUM_SERVERS` | `3` | Number of servers. |
| `BASE_GAME_PORT`, `BASE_TV_PORT` | `27015`, `27020` | Ports of server 1. |
| `HOSTNAME_PREFIX` | `CS2 Server` | Start of each server name. |
| `RCON_PASSWORD` | a fixed default | RCON password. Always set it. |
| `MATCHZY_DB_ENGINE` | `mysql` | MatchZy Enhanced stack: `sqlite` for one SQLite file per server. |
| `MATCHZY_SKIP_DOCKER` | `0` | MatchZy Enhanced stack: `1` to skip the MySQL container. |
| `ENABLE_METAMOD` | `1` | MatchZy Enhanced stack: `0` to install without Metamod. |
| `UPDATE_MASTER` | `1` | `0` to skip the game update. |
| `FRESH_INSTALL` | `0` | `1` to start over from a clean install. |

## If `steamcmd` cannot be installed

`E: Unable to locate package steamcmd` means your apt sources do not include the part that has SteamCMD. `sudo csm install-deps` tries to fix this: it turns on the missing part in `/etc/apt/sources.list`, saves a backup next to it, and tries again.

To do it by hand on Ubuntu:

```bash
sudo add-apt-repository multiverse
sudo apt-get update
sudo apt-get install steamcmd
```

On Debian, add `contrib` and `non-free` to your apt sources, then run `sudo apt-get update` and `sudo apt-get install steamcmd`.

## Remove everything

This deletes all servers and the MySQL container:

```bash
csm cleanup-all
```
