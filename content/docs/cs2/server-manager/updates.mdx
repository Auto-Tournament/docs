## Update CS2

Valve updates CS2 often. An outdated server cannot load matches, and Auto Tournament shows **CS2 update required**.

```bash
sudo csm update-game
```

This updates `master-install` with SteamCMD, stops all servers, copies the new files to each server and starts them again. Players on the servers are kicked, so do not run it during a match.

To update only one server:

```bash
sudo csm update-server 2
```

## Update the plugins

```bash
sudo csm update-plugins
```

This downloads the plugins, copies them and your [overrides](/cs2/server-manager/configuration#your-own-config-files) to every server, and restarts the servers. It installs:

- **Metamod:Source `2.0.0.1411`.** This version is fixed on purpose. Metamod builds from 2026-09-08 do not work with the current CounterStrikeSharp release, which then fails with `Plugin uses old SourceHook Metamod build`.
- **CounterStrikeSharp**, the latest release.
- **[Auto Tournament CS2](/cs2/plugin)**, the latest release.

`update-plugins` always installs the whole bundle, so it replaces a newer Metamod with the fixed version. To choose another Metamod build, set `CSM_METAMOD_VERSION` to a [release tag](https://github.com/alliedmodders/metamod-source/releases), or to `latest` for the newest build:

```bash
sudo CSM_METAMOD_VERSION=2.0.0.1468 csm update-plugins
```

Keep all servers on the same plugin version. Auto Tournament shows **Version mismatch** when they differ.

## The update monitor

The update monitor checks each server's log and updates servers that need it. Install it as a cron job that runs every 5 minutes:

```bash
sudo csm install-monitor-cron
```

Other intervals use cron syntax for the minute field:

```bash
sudo csm install-monitor-cron "*/10"
```

To remove it:

```bash
sudo csm remove-monitor-cron
```

To run one check by hand:

```bash
sudo csm monitor
```

### How the monitor works

When Steam reports a new CS2 version, the plugin writes this line to the server log:

```text
[MATCHZY_UPDATE_AVAILABLE] required_version=<number>
```

The monitor looks for this line in each server's log. When it finds one:

- A **stopped** server is updated and started.
- A **running** server is updated only when it is idle. That means no players are connected, no match is loaded, and both have been true for the idle grace period (10 minutes by default). The monitor asks the server over RCON: `status` for players, and the plugin's `get5_status` for the match. If the server doesn't answer, the monitor treats it as busy and waits.
- If **updates are on hold**, the monitor only logs that an update is available and restarts nothing. See [Hold updates during an event](#hold-updates-during-an-event).

To update an idle server, the monitor announces the restart in chat, stops the server, updates it, starts it and checks that it answers RCON again. It does this one server at a time and never touches a server with players on it.

The plugin's default `matchzy_safeautoupdater_action warn_only` is fine for this. The server keeps running and the monitor restarts it once it is idle.

After an update, the monitor waits an hour before it updates the same server again, so a server that keeps reporting an update does not restart in a loop.

The monitor writes its log to `auto_update_monitor.log` in the `csm` log folder. Run `csm logdir` to find it.

### Hold updates during an event

The monitor can't see whether a tournament is running. It only sees whether a server is idle, and servers are often idle between matches. Before an event, turn automatic updates off:

```bash
sudo csm updates hold on
```

While the hold is on, the monitor never restarts a server. When the event is over:

```bash
sudo csm updates hold off
```

The hold is saved and survives reboots. `csm update-game` and `csm update-server` still work while it is on, so you can update by hand between rounds.

To see the current settings:

```bash
sudo csm updates status
```

### Change the idle grace period

A server must stay idle this many minutes before the monitor updates it:

```bash
sudo csm updates grace 20
```

## Set up automatic updates

Install the update monitor:

```bash
sudo csm install-monitor-cron
```

That's it. When CS2 updates, each server is updated the next time it has been idle for the grace period. Remember to run `sudo csm updates hold on` before an event.
