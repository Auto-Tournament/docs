The platform doesn't run CS2 itself. It runs CS2 dedicated servers on **machines**: Linux computers with [CS2 Server Manager](/cs2/server-manager) (`csm`). You link a machine once with one command; from then on the platform creates, starts, stops and updates its servers, and each server talks to the platform over its own connection (Ready Up's fleet link). No RCON passwords and no addresses to type in.

## What a machine needs

- Linux (Debian or Ubuntu) on `x86_64` or `arm64`, and an account with `sudo`. The servers run as that account.
- About 71 GB of disk for CS2, plus about 2 GB per server, and 8 GB RAM or more.
- It reaches the platform at `FRONTEND_BASE_URL`. The platform never connects to the machine, so the machine needs no open inbound port for the platform; players need the game ports (UDP `27015`, `27025`, … one per server).
- No Game Server Login Token: players join from the match page. See [Game Server Login Token](/modules/cs2/server-requirements#game-server-login-token).

How many servers per machine depends on the CPU: a match server mostly uses one or two cores. One server on a 4-core mini PC is comfortable; a big server takes many.

<Steps>

<Step>

### Add the machine in the dashboard

Open **Servers** > **Add machine** and give the machine a name. It shows one line to copy:

```bash
curl -fsSL https://cs.example.com/api/fleet/install-csm.sh | bash -s -- RUE-7F3K-9QX2-LM4D-P8TW
```

The code works once and runs out after 15 minutes. (No Servers page? Install **Counter-Strike 2** under **Modules**, or pick it at the end of setup.)

</Step>

<Step>

### Run it on the machine

Log in to the machine as the account the servers will run as (not root) and paste the line. It installs `csm` if it isn't there, asks for `sudo` once to prepare the machine (SteamCMD, tmux, services that keep running after you log out), links the machine and starts csm's agent. The dashboard says **Connected** within a few seconds.

The servers run [Ready Up](/cs2/ready-up) under the license accepted on the platform ([License](/guides/license)); the machine needs no answer of its own. On a platform served over plain `http://` (fine on a LAN) the link uses `--insecure`; on the internet, put the platform behind HTTPS.

</Step>

<Step>

### Create servers

On the machine's card, click **Create server**. The first one downloads CS2 (about 70 GB), which takes a while; the next ones take a minute. Each server installs Ready Up, enrolls itself on the platform and shows as a tile on the machine: **Free** when it's ready for a match.

Create as many as you want to run matches at the same time. **Fleet settings** on the Servers page has automatic scaling, which creates and stops servers by itself as tournaments need them.

</Step>

</Steps>

## Good to know

- `csm status` on the machine lists its servers with map, score and players. `csm` without arguments opens a menu.
- csm doesn't restart a server for a CS2 update while a match is loaded or live on it.
- A machine linked again (to a new install of the platform, say) keeps its servers: the platform gives them a new key and they enroll by themselves within a minute or two.
- Servers come only from machines. Servers added by address with an RCON password (the 2.x way) are gone; link their machine with csm instead.
- Problems: [csm troubleshooting](/cs2/server-manager/troubleshooting) and [Ready Up troubleshooting](/cs2/ready-up/troubleshooting).
