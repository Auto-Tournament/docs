Auto Tournament runs as two containers: the app and a PostgreSQL database. You need a Linux, macOS or Windows machine with [Docker](https://docs.docker.com/engine/install/) and Docker Compose.

<Callout title="Coming from 2.x?">
  3.0 has a new image, new container names and a renamed database. Follow [Upgrading to 3.0](/guides/upgrading-to-3) instead of this page.
</Callout>

<Steps>

<Step>

### Create a folder

```bash
mkdir -p autotournament && cd autotournament
```

</Step>

<Step>

### Save `docker-compose.yml`

Save this file as `docker-compose.yml` in the folder:

```yaml title="docker-compose.yml"
services:
  postgres:
    image: postgres:16-alpine
    container_name: auto-tournament-postgres
    restart: unless-stopped
    environment:
      - POSTGRES_USER=${DB_USER:-postgres}
      - POSTGRES_PASSWORD=${DB_PASSWORD:-postgres}
      - POSTGRES_DB=${DB_NAME:-auto_tournament}
    volumes:
      - postgres-data:/var/lib/postgresql/data
    healthcheck:
      test: ['CMD-SHELL', 'pg_isready -U ${DB_USER:-postgres}']
      interval: 10s
      timeout: 5s
      retries: 5
    networks:
      - auto-tournament-network

  auto-tournament:
    image: sivertio/auto-tournament:next
    container_name: auto-tournament
    restart: unless-stopped
    depends_on:
      postgres:
        condition: service_healthy
    env_file:
      - .env
    ports:
      - '${HOST_PORT:-3069}:3069'
    environment:
      - NODE_ENV=production
      - PORT=3000
      - DB_HOST=postgres
      - DATABASE_URL=postgresql://${DB_USER:-postgres}:${DB_PASSWORD:-postgres}@postgres:5432/${DB_NAME:-auto_tournament}
      - SESSION_SECRET=${SESSION_SECRET:-}
    volumes:
      - ./data:/app/data
    healthcheck:
      test: ['CMD', 'wget', '--no-verbose', '--tries=1', '--spider', 'http://localhost:3069/health']
      interval: 30s
      timeout: 3s
      retries: 3
      start_period: 10s
    networks:
      - auto-tournament-network

networks:
  auto-tournament-network:
    driver: bridge

volumes:
  postgres-data:
    driver: local
```

`:next` is the 3.0 beta. When 3.0.0 is out, use `:latest`. The same image is on GitHub as `ghcr.io/auto-tournament/auto-tournament`.

`PORT=3000` is the internal port of the API. Do not change it. The web app and API are both served on port `3069`. Set `HOST_PORT` in `.env` to use another port on your machine.

</Step>

<Step>

### Create `.env`

This command creates `.env` with two new random secrets:

```bash
cat > .env <<EOF
SESSION_SECRET=$(openssl rand -base64 32)
SERVER_TOKEN=$(openssl rand -base64 24 | tr -d '=+/')
FRONTEND_BASE_URL=http://localhost:3069
LOG_LEVEL=info
EOF
```

Then set `FRONTEND_BASE_URL` to the address you open in the browser. Game servers also use it to reach the platform, so `localhost` only works when they run on the same machine. Otherwise use the LAN IP or domain, for example `http://192.168.1.50:3069` or `https://tournament.example.com`.

Sign-in providers, such as the Steam Web API key, are set up later in the app (**Settings → Sign-in**), not here. All other settings are in [Configuration](/reference/configuration).

</Step>

<Step>

### Start

```bash
docker compose up -d
```

Check that it is running:

```bash
curl -fsS http://localhost:3069/health
```

</Step>

<Step>

### Open the app

Open the value of `FRONTEND_BASE_URL` in your browser, for example [http://localhost:3069](http://localhost:3069). Continue with [First login](/getting-started/first-login).

</Step>

</Steps>

## Where the data is

- The database is in the Docker volume `postgres-data`. `docker compose down` keeps it. `docker compose down -v` deletes it.
- Uploaded files, such as demos and installed game modules, are in the `data/` folder next to `docker-compose.yml`.

Before you update, read [Updating](/guides/updating).

## Use a domain with HTTPS

Put a reverse proxy in front of port 3069 and set `FRONTEND_BASE_URL` to the `https://` address. See [Reverse proxy](/guides/reverse-proxy).
