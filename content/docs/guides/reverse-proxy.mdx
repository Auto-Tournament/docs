Auto Tournament serves the web app, the API and the live updates (WebSocket) on one port, `3069`. To use a domain with HTTPS, put a reverse proxy in front of that port.

<Steps>

<Step>

### Point the domain at your machine

Create a DNS record for your domain, for example `tournament.example.com`, that points to the machine that runs Auto Tournament. Open ports 80 and 443 in the firewall.

</Step>

<Step>

### Set up the reverse proxy

Use [Caddy](#caddy) or [nginx](#nginx) with the config below. Both forward the domain to `127.0.0.1:3069`.

</Step>

<Step>

### Set the public address

In `.env`, set `FRONTEND_BASE_URL` to the address people open in the browser:

```bash title=".env"
FRONTEND_BASE_URL=https://tournament.example.com
```

With an `https://` address, login cookies are only sent over HTTPS.

</Step>

<Step>

### Recreate the app container

```bash
docker compose up -d --force-recreate auto-tournament
```

</Step>

<Step>

### Update the webhook URL

Open **Settings → Counter-Strike 2 → Webhook URL**. Your CS2 servers and links use this address to reach the site. Change it to the new domain if it still shows the old address.

</Step>

</Steps>

## Caddy

Caddy gets a certificate for you:

```text title="Caddyfile"
tournament.example.com {
    reverse_proxy 127.0.0.1:3069
}
```

## nginx

```nginx title="/etc/nginx/sites-available/autotournament"
server {
    listen 80;
    listen [::]:80;
    server_name tournament.example.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    listen [::]:443 ssl;
    server_name tournament.example.com;

    ssl_certificate     /etc/letsencrypt/live/tournament.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/tournament.example.com/privkey.pem;

    client_max_body_size 0;

    location / {
        proxy_pass http://127.0.0.1:3069;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}
```

- `X-Forwarded-Proto` tells Auto Tournament that the page uses HTTPS. Without it, login can fail.
- `Upgrade` and `Connection` let the live updates use WebSocket.
- `client_max_body_size 0` removes the upload limit. Demo files are large, and the nginx default of 1 MB blocks demo uploads.

## Cloudflare

Behind Cloudflare, either with the domain's DNS record proxied (orange cloud) or with a [Cloudflare Tunnel](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/) (`cloudflared`) pointing at `http://localhost:3069`, add one cache rule. WebSocket works without changes.

Clips and reels keep their file name when they are recorded again, and Auto Tournament asks for them to be cached for five minutes. Cloudflare raises that to your zone's browser cache time, four hours by default, so after a clip is recorded again, viewers keep getting the old video for hours.

In the Cloudflare dashboard, open **Caching → Cache Rules** and create a rule:

- **When:** hostname equals `tournament.example.com` and URI path starts with `/api/game/cs2/highlights/`
- **Cache eligibility:** eligible for cache
- **Edge TTL:** use cache-control header if present
- **Browser TTL:** respect origin TTL
