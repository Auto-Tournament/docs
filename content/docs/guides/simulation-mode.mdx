In simulation mode, every match is played by bots. The veto is done automatically. Use it to test your servers, your bracket and your settings before an event.

<Callout type="warn">
  Only use simulation mode on a test install. It changes how every match on the install is played.
</Callout>

## What you need

- A test install of Auto Tournament.
- At least one CS2 server with MatchZy Enhanced, added on the **Servers** page.
- Teams, or players for a shuffle tournament. The players do not need to be real Steam accounts that join.

## Turn it on

Simulation is off in production builds. You must allow it with an environment variable, and then switch it on.

### 1. Allow it

Add this line to `.env` and recreate the app container:

```bash title=".env"
MATCHZY_ENABLE_SIMULATION_IN_PROD=true
```

```bash
docker compose up -d --force-recreate matchzy-tournament
```

### 2. Switch it on

The switch is on the **Developer / Simulation** tab in **Settings**. The published Docker image does not show this tab. Pick one of these two ways.

**With the API.** Create an admin API token (see [API](/reference/api)) and run:

```bash
curl -X PUT http://localhost:3069/api/settings \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"simulateMatches": true, "simulationTimescale": 2}'
```

Send `{"simulateMatches": false}` to switch it off again.

**With a build from source.** The local build shows the **Developer / Simulation** tab and a **Dev Tools** page, and it allows simulation already:

```bash
git clone https://github.com/sivert-io/matchzy-auto-tournament.git
cd matchzy-auto-tournament
cp example.env .env
```

Set `SESSION_SECRET`, `SERVER_TOKEN` and `STEAM_API_KEY` in `.env`, then:

```bash
docker compose --env-file .env -f docker/docker-compose.local.yml up -d --build
```

The local build does not keep the database in a volume. Your data is gone when you remove the containers.

## Speed

**Simulation Timescale** sets how fast the bots play, from 0.1 to 10. Values above 2 can make bots act strangely. Speeds above 4 need MatchZy Enhanced 1.4.25 or newer. The value is sent when a match loads, so a change only affects matches that load after it.

For a fast test bracket, create the tournament with **Max Rounds per Map** set to 4 and overtime set to **Disabled – no draws (damage tiebreak)**. Every map then ends after at most 4 rounds and always has a winner.

The timescale does not change the wait after a series ends. The plugin keeps the server for a while before it resets, and the next match on that server loads after the reset. That wait is `mp_match_restart_delay` plus the `matchzy_series_end_kick_delay_*` settings on the server, with 60 seconds extra when demos are uploaded. Lower them on test servers if the next match starts too slowly.

## Start over

On a build from source, **Dev Tools** has **Reset Simulation State**. It deletes all matches and stats, and keeps servers, teams, maps and the tournament setup. Then you can start the same tournament again.
