- **MINOR**: X.Y.0

## v2.4.13 (2026-09-16) — **PATCH**

### Fixes

- Keep rating history when a tournament is deleted. Deleting a tournament removed its matches' rating history while players kept their ratings. History rows now keep the match label and tournament name, and existing databases are migrated on start. Resetting a tournament still removes that run's history

## v2.4.12 (2026-09-16) — **PATCH**

### Fixes

- Fix **Test connectivity** on the servers page returning an error for every server. The server modal now also shows the error inline
- Stop ratings from stacking up across tournament resets. A reset deleted the matches and their rating history but kept the players' ratings, so each run built on the last. A reset now puts each player back to their rating from before their first match of that run
- Start the rating history and chart on the player page at the player's starting rating
- Send `mp_match_restart_delay 10` in simulated match configs

## v2.4.11 (2026-09-16) — **PATCH**

### Features

- Free a server for the next match as soon as it is idle and its demo upload has reported back, instead of waiting about 3 minutes after the series ends. A server whose demo is still uploading is held, for at most 15 minutes
- Simulated matches use `tv_delay 0` and 10 second series-end kick delays, so their demos stop and upload right away. Real matches keep the server's `tv_delay` and your kick delays
- A demo upload that never reports back holds a server for at most about 5 minutes (`tv_delay` + 15 seconds + the 150 second upload timeout) instead of 15 minutes, with a warning in the log

### Fixes

- Show the same Swiss standings on the bracket page and the leaderboard as the round pairing uses: wins, losses, Buchholz, round difference, seed. `GET /api/tournament/bracket` returns `swissStandings`, and the leaderboard adds rank, Buchholz and round difference
- **Save & Generate** with no changes now leaves the wizard instead of staying on the review step
- **Test connectivity** no longer changes the server's event URL. Servers that are not set up show as unknown
- Show a readable message when a proxy returns an HTML error page, such as a 502
- Team page: tournament status when the team has no match, roster ratings, rank among the tournament's teams, and match labels in play order in the history
- Send an admin who views the app as a player to that player's page, and hide the admin menu while doing so
- On small screens the menu opens as a drawer and starts closed
- Explain on map chips and in the match window when a map was decided by a tiebreak

### Ops/Docs

- Update the example Discord bot for the 2.4.10 API: bracket labels, matches that need a decision, the champion, and scores read from the explicit series and map score fields

## v2.4.10 (2026-09-16) — **PATCH**

### Fixes

- Fix Swiss tournaments getting stuck after round 1. Advancing the round failed with a database error on the last result of the round, and nothing paired the later rounds anyway. Rounds 2 and on are now paired from the standings when the previous round is done: teams with the same record play each other, the lowest team of an odd group moves down, rematches are avoided, and odd team counts get one bye per round (never a second bye for a team while another has none). Tournaments already stuck are paired the next time the tournament is loaded. See [Match rules and formats](/guides/tournament-formats#swiss)
- Complete a Swiss tournament after its last round and name the top of the standings as champion. Standings count byes and sort by wins, losses, Buchholz and round difference
- Show "Waiting for pairing" on unpaired Swiss matches instead of "Veto pending", and "BYE" for a bye
- Show the format as "Best of 3" in the review-changes dialog instead of `bo3`
- Report the last map's rounds as the map score on completed matches, instead of nothing

## v2.4.9 (2026-09-16) — **PATCH**

### Features

- Add a **Needs decision** status for elimination series that run out of maps while level. MAT first decides such a series itself on maps won, then rounds, then damage. If that is still level, the server is freed and an admin picks the winner in the match window, or with `POST /api/matches/:slug/winner`. Progression, stats and ratings apply as for a normal series end. This also works for a match stuck in live or loaded. See [Match rules and formats](/guides/tournament-formats#when-a-series-ends-level)
- Label double elimination matches "UB R1 M1", "LB R2 M1" and "Grand Final" on match cards, the list view, the match window and server chips

### Fixes

- Fix double elimination series that ran out of maps without a winner never ending, which held up the rest of the bracket. Swiss and round robin still allow a drawn series
- Queue double elimination matches in play order: upper and lower bracket rounds alternate, and the grand final comes last. Only matches with both teams get a queue position
- Stop match reports from changing the map number of a finished match
- Name the upper bracket final and lower bracket final in the grand final's empty slots
- List a changed grand final mode in the wizard's confirm dialog, and apply the double elimination default (Simple) when switching type
- Clear live stats when a tournament is deleted. Match slugs are reused, so a new match could start with the old one's series score

## v2.4.8 (2026-09-16) — **PATCH**

### Fixes

- Fix servers staying "busy" after a restart. With autostart on, the plugin puts an empty server in warmup, and MAT treated every warmup as a running match. Warmup with no match loaded now counts as free
- Give servers to matches in queue order. Each ready match polled on its own timer, so whichever polled first after a server freed up took it, and match 3 could start before match 2
- Stop applying plugin reports from an idle server to the match it finished last. Reports now only apply to the match that server is running
- Fix the stored config after a simulated veto ignoring the tournament's max rounds and overtime. Servers already got the right config, but the stored copy showed 24 rounds
- Keep `settings.matchFormat` in sync with the format after editing a tournament
- Show "Winner of" and the feeder match in empty bracket slots instead of "#1" and "#2", which looked like seeds but were not
- Fix the "You" chip on a team roster pointing at the wrong player when viewing someone else's profile
- Translate the servers page, admin tools, match admin controls and the remaining wizard text, and fix plurals that showed raw text such as "3 server3}"
- Move noisy log lines (match config dumps, allocation status on every poll, player lists) to debug, and fix "SERIES ENDED: undefined 0-1 undefined"

## v2.4.7 (2026-09-16) — **PATCH**

### Features

- Show the champion on the tournament and bracket pages once a tournament is done. `GET /api/tournament` returns it as `winner`
- Add separate score fields to the match API: `team1SeriesScore`/`team2SeriesScore` for maps won, and `team1MapScore`/`team2MapScore` for rounds on the current map
- Offer all three overtime options in the tournament wizard and shuffle setup, including "Disabled – no draws (damage tiebreak)", which was API-only. The review step now lists max rounds and overtime
- Translate the team page and the remaining English text, and fill every missing key in all locales

### Fixes

- Fix one match running on two servers at once. A load sent to a server still in postgame was queued by the plugin, MAT took it as failed and loaded the match somewhere else, and results from both servers were applied. MAT now reads server status correctly, treats a queued load as loaded, cancels queued loads it no longer wants, and ignores events and config fetches from a server the match is not assigned to
- Fix demos being saved under the next match. The upload URL is per server and was already pointing at the next match when the previous demo finished. Uploads now go to the match the demo was recorded for
- Fix live Bo3 scores mixing one team's rounds with the other team's maps won, such as "23 vs 1"
- Fix match history showing 0 kills and 0 damage for everyone when the plugin filed players under the wrong team
- Stop the header covering the impersonation banner, so the button to stop viewing as a player can be clicked
- Keep the veto board visible when an action is refused, with the error shown above it
- Show a server as busy during a live match even when the plugin still reports idle
- Show no score during warmup between maps, instead of the previous map's score
- Fix "Total Change" in the ELO summary using a different starting rating than the history above it
- Stop the wizard changing settings it does not show, such as turning the grand final mode into "none" on save
- Say the tournament is waiting on vetoes or servers, not "live", before any match has loaded

### Ops/Docs

- Push the release version bump straight to main instead of opening a bot pull request, which left a failed CI run on every release
- Check in CI that no locale is missing translation keys

## v2.4.5 (2026-09-15) — **PATCH**

Versions 2.4.2 to 2.4.4 were never published. Their release builds failed before any image was pushed, and the tags were removed.

### Fixes

- Fix Bo3 and Bo5 series being marked finished after the first map. The plugin reports `postgame` between maps, and MAT treated that as the end of the match, so the winner never advanced in the bracket and the rest of the series was ignored. Only the real series end completes a match now. A match that was closed this way opens again when the server keeps sending events for it
- Fix setting up a server that another MAT instance had configured before. MAT sent the bootstrap URL before the new token, so the plugin fetched its config with the old token, got a 401 and never received its config. The token is now sent first
- Stop reporting "Failed to end match" when a tournament reset restarts a server. The server restarts before it can answer the RCON command, so the missing reply is now treated as sent
- Complete pending map vetoes when simulation mode is turned on while a tournament is running. Before, only matches that started after that point got an automatic veto
- Fix the veto page saying the opponent had made their choice right after your own ban or pick
- Show translated action names in the veto history instead of raw values such as `SIDE_PICK`
- Translate the remaining text on the veto and match pages. Norwegian has all the new text; other languages show English for it until translated
- Make veto map tiles real buttons, so a veto can be done with a keyboard or a screen reader
- Remove leftover debug output from the API logs, which printed veto state and map lists every time a match loaded

### Ops/Docs

- Build the arm64 release image natively instead of under QEMU, where builds had started crashing, and push images before creating the tag
- Split the E2E tests across parallel CI jobs, build the test image once, and skip E2E for pull requests that only change docs

## v2.4.0 (2026-09-15) — **MINOR**

### Features

- Store a Discord ID on each player, so a Discord bot can find the player behind a Discord user. Admins set it in the player editor, players set their own on their profile page, and team imports fill it in. An import only fills an empty ID and never changes one that was set or removed by hand. Only admins and API tokens can read it
- Add `GET /api/players/by-discord-id/{discordId}`, which works with a read-only API token. It returns a list, because a parent may put their own Discord ID on several children
- Add a `/mymatch` command to the example Discord bot, which shows the current match of the player (or players) behind the Discord user who ran it

### Fixes

- Check OAuth `state` on the Discord, GitHub and Keycloak login callbacks. Without it, a link could attach an attacker's SSO account to an admin who had signed in with Steam, and the attacker could then sign in as that admin. Steam-only instances were not affected
- Sign the `pending_steam_link` cookie. It was plain JSON, so anyone could point someone else's Discord, GitHub or Keycloak login at their own Steam account
- Clear the Steam, pending-link and impersonation cookies on logout. `/logout` also chose the cookie's `secure` flag from `NODE_ENV` rather than the connection, so on a production install served over plain HTTP the cookie was never cleared
- Stop logging OAuth access and refresh tokens at info level on SSO callbacks

### Ops/Docs

- Generate release notes from squash-merged pull requests. Earlier releases on GitHub listed only the version bump

## v2.3.0 (2026-09-07) — **MINOR**

### Features

- Add API tokens (`API_TOKENS`, `API_TOKENS_READONLY`) so a bot or script can call the admin API without signing in through a browser
- Publish an OpenAPI spec covering every endpoint, at `/api-docs.json` and in the repository, so you can generate a client in any language
- Add an example Discord bot under `examples/discord-bot`, with a scoreboard that updates itself while a match is played

### Fixes

- Require `X-MatchZy-Token` on the game event webhooks. They accepted events from anyone who could reach the API, so anyone could report match results. Servers that MAT set up already send the token. Set `ALLOW_UNAUTHENTICATED_EVENTS=true` to keep accepting events without one while you reconnect a server that does not
- Fix `/api-docs` and `/api-docs.json` returning the dashboard instead of the API documentation. The reverse proxy in the Docker image only forwarded paths under `/api/`, so Swagger UI had never worked in a Docker deployment
- Fix the OpenAPI spec served by the Docker image having no descriptions. The image ships bundled JavaScript, and the descriptions are read from the TypeScript sources, which are not in it
- Fix three `/api/templates/{id}` endpoints appearing twice in the OpenAPI spec, from documentation comments written with Express-style `:id` instead of `{id}`

### Ops/Docs

- Generate the endpoint reference and the OpenAPI spec from the Express routers, and fail CI when either drifts from the code
- Add a guide for calling the API from a bot or script, with a worked Discord scoreboard example
- Mark routes that are registered twice and never reached. `GET /api/tournament/{id}/leaderboard` is registered both before and after the admin guard, so it answers without one
